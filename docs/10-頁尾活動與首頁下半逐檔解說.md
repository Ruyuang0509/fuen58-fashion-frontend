# 10　第十五輪・子輪 1：頁尾、首頁下半、活動、六套新穿搭

2026-10-06。使用者把這一輪（內容／功能拓展）的所有裁決交給 Claude（「以上項目全部允許你自主判斷」）。規格與四個子輪的拆法在 [09](09-內容與功能拓展-規格.md)；這份是子輪 1 做了什麼、每個檔為什麼這樣寫。

## 做了什麼（一句話）

店不再是「一片格子然後結束」：格子裡夾了活動的插卡，格子之後有「新上架」「熱銷」兩排單品，最底下是整站地圖式的頁尾；多了「活動」這種資料與活動頁；穿搭從 12 套變 18 套，每條路線至少兩套。

## 逐檔

### 資料與 API

- `src/api/mock/campaigns.json`（新）：四檔假活動。欄位：`code`、`title`、`tagline`、`startsAt`／`endsAt`、`themeCode`（天空與顏色跟它）、`brandCodes`、`outfitIds`、`productIds`、`placements`（`stage` 舞台插卡｜`footer` 頁尾）。`summer-linen` 已經結束，故意留著驗證過期的處理。文案不寫捏造的數字。
- `src/api/index.js`：
  - `getCampaigns({ active, theme, placement })`、`getCampaign(code)`。進行中與否在這裡算：`startsAt ≤ 今天 ≤ endsAt`，今天用 `Intl.DateTimeFormat('sv-SE', { timeZone: 'Asia/Taipei' })` 取臺北的日期字串（`sv-SE` 的格式剛好是 ISO 的 `YYYY-MM-DD`），所以 `endsAt` 含當天，畫面不用自己比日期。活動物件多帶展開後的 `outfits`（插卡與活動頁的人形用）。
  - `getOutfits` 多一個 `ids`：只要這幾套、照給的順序（活動頁的店用）。
- `src/api/mock/outfits.json`：加六套（13 舊書店的下午／復古、14 後台的走廊／龐克、15 星期天的花園／蘿莉塔、16 放學後的咖啡店／量產型、17 末班車／街頭、18 週末的步道／戶外），用現有的 35 件單品換顏色與組合，沒有加商品。每條路線至少兩套；女生 8、中性 6、男生 3、小孩 1——`?for=women` 14 套、`?for=men` 9 套。副作用：商品所屬的路線是「出現在哪些路線的穿搭裡」算出來的，所以百褶短裙與毛帽現在也算龐克路線，搜尋「龐克」從 3 件變 5 件（shop-check 的期望值跟著改）。
- `src/config.js`：`REPO_URL`——頁尾唯一的外連。

### 活動放在哪

- `src/components/CampaignTile.vue`（新）：舞台裡的插卡。活動色底（所屬路線的 accent，本來就是給白字當底的顏色）、白字、襯線標題、一句話、期間（Space Mono，不拆行）、「看這檔活動 →」、右邊放它第一套穿搭的人形（`OutfitLook`，不帶文字）。用容器查詢：格子窄於 24rem 時人形改到字的下面。整塊是連到活動頁的連結。
- `src/components/OutfitStage.vue`：接 `campaigns`（要插哪幾檔）、`ids`（只列哪幾套）、`waiting`（外面還沒拿到活動時先顯示載入中，不閃一下「沒有符合的穿搭」）。窄螢幕的欄距歸零、中等寬度縮小（原因見「實測」第 3 點）；每個格子 `min-width: 0`。穿搭與插卡合成一列 `cells`：第 1 張插卡在第 4 張穿搭之後、第 2 張在第 10 張之後——寬度循環是 4-5-3／3-5-4，第 5 格與第 11 格剛好都是最寬的 span 5，插卡落在那裡字和人形才放得下；穿搭不夠就插在最後。插卡 `align-self: stretch` 撐滿那一列（卡片對齊頂端、高矮不一，插卡像一整頁夾頁而不是半空的小方塊）。`TransitionGroup` 裡用 `<component :is>` 切兩種元件，key 分別是 `outfit-<id>`、`campaign-<code>`。
- `src/views/explore/CampaignHero.vue`（新）：活動頁 `/campaigns/:code` 的第一屏，是 `ExploreView` 的子路由（活動就是一條限時的路線）。天空用所屬路線的時刻與顏色；左邊「活動／期間」、標題、一句話、「其他活動」；右邊最多三套人形；過期多一行「已經結束」。寫法與 `ThemeHero` 同一套。
- `src/views/ExploreView.vue`：殼自己也抓那檔活動——店的標題「○○的穿搭」、`OutfitStage` 的 `ids`、底下「這檔活動的單品」一排。插卡的規則：首頁與全部穿搭插全部進行中的（最多兩檔，快結束的優先）、路線頁只插同路線的、活動頁不插。首頁最後接 `HomeShelves`。
- `src/router/index.js`：殼多一個子路由 `campaigns/:code`（name `campaign`）。
- `src/views/ProductView.vue`：多一排「○○（品牌）的新品」——同品牌、排除自己、新上架前 4；標題裡的品牌名連到品牌頁。款式圖在手機上跟著欄寬縮（見「實測」第 4 點）。
- `src/components/SiteHeader.vue`：手機上搜尋開啟時，整條搜尋列蓋在頂欄那一列上（見「實測」第 5 點）。

### 首頁下半與搜尋頁

- `src/components/HomeShelves.vue`（新）：只在首頁、穿搭格子之後。「新上架」8 件、「熱銷」8 件，各一排橫向可捲（`grid-auto-flow: column`、`scroll-snap`），熱銷每張卡左上一個大號等寬數字。`.shelf` 要 `min-width: 0`——grid item 預設不能比內容窄，第一次跑時整頁被撐出 600 多像素的橫向捲動，實測抓到才知道。「看全部」連到 `/search?sort=new`／`?sort=popular`。

### 頁尾

- `src/components/SiteFooter.vue`（重寫）：五欄——路線（8）、品牌（6）、找單品（全部單品、新上架、熱銷、只看有貨、全部穿搭、給小孩的穿搭）、現在的活動（進行中的才列，沒有就整欄不出現）、關於（關於本專題錨點、GitHub 專案、給後端的契約、穿搭牆「籌備中」不是連結）。第一版多一欄「會員」放登入／註冊，子輪 2 後使用者說「沒人會在 footer 放這個」，拿掉了。底部保留原本兩行聲明＋站名＋「回到最上面」。底色 `color-mix(in srgb, var(--accent) 6%, var(--bg))`，跟著路線色微染；手機兩欄。**不放社群圖示**：品牌全虛構、專題沒有真的社群帳號，連到空頁的 IG／FB 是我最不想做的事。

## 實測了什麼

- `npm run build` 成功；`expand-check` 47／47、`shop-check` 60／60、`member-check` 39／39——三支都在 1252×699 與 390×844 跑過，而且是用改過的溢出檢查；對比 42 組全過；無頭 Chrome 全程沒有主控台錯誤。
- 截圖看過（`docs/r15-shots/`）：頁尾六欄（桌機）與兩欄（手機）、活動頁第一屏（桌機與手機）、戶外路線頁的三套、插卡落在寬格、綠底插卡的字與人形。
- **跑驗收抓到的問題（都修了）**：
  1. 首頁橫向溢出 617px：橫向可捲那一排是 grid item，預設不能比內容窄（`.shelf { min-width: 0 }`）。
  2. 插卡落在窄格時期間拆行、字只剩兩三字一行：改插在第 4 與第 10 張之後（最寬格），窄格用容器查詢把人形移到字下面。
  3. **手機上整列卡片都是 563px、跑出 390 的視窗**——我連猜三次都錯（容器查詢、`keep-all`、item 的 `min-width`），最後在同一個 Chrome session 把軌道寬度、每張卡的框、`innerWidth／clientWidth／scrollWidth` 一起印出來才看到：12 條軌道全是 0px，**11 條 3.2rem 的欄距加起來就是 563px**，比視窗還寬。窄螢幕欄距歸零（`gap: var(--s4) 0`）、中等寬度欄距縮成 1.6rem。
  4. 商品頁在 390 寬溢出 71px：款式圖的 PNG 是 384px 寬加按鈕留白（圖 `max-width: 100%`、gallery 的 item `min-width: 0`）。
  5. 搜尋頁在 390 寬溢出 31px：頂欄搜尋開啟時輸入框硬塞在圖示旁（改成整條搜尋列蓋在頂欄那一列上）。
- **為什麼以前全綠**：三支腳本的「無橫向捲動」都算 `scrollWidth − innerWidth`，但手機模擬（`mobile: true`）下**版面視口會跟著溢出的內容長大**，兩個數一起變 589、相減永遠是 0；要和 `clientWidth` 比。三支腳本一起改，另加「可見元素右緣超出視窗」的偵測（跳過橫向可捲容器裡的東西）與兩個正控：注入 3000px 寬的元素一定要被抓到、`clientWidth` 一定要等於要求的寬度。4 與 5 是這個改動之後才現形的舊問題。

**沒有驗證**：使用者本人；手機實機；插卡撐滿列高之後在中等寬度（兩張一列）的觀感只看了程式沒截圖；讀屏。
