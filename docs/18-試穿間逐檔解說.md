# 18　第十六輪・子輪 3：試穿間

2026-10-10。規格在 [15](15-天氣接到穿搭與尺寸推薦-規格.md) §6；功能規劃 6.5「試穿人偶」是 `加`、停損日 11/23、「先試做」——這是那個試做版。自主探索的第三個子輪，設計沒有一項經過確認。

## 做了什麼（一句話）

`/fitting`：外層、上身、下身三件疊成一個人形（沿用穿搭卡那套疊法），用一句話換件換色——「外層穿［落肩混紡大衣］的［燕麥］，上身穿［圓領細針織上衣］的［米白］，下身穿［直筒西裝褲］的［墨黑］。」狀態寫在網址，可以直接貼給人；人形依身形略為縮放（示意）；整套加入購物車。穿搭頁有「拿這套去試穿間改」，單品頁有「放進試穿間」（只換那一層，其他兩層沿用上一次的）。

## 設計怎麼定的

- **不做 3D、不做布料模擬、不另備去背圖**：功能規劃 6.5 寫的「每件需額外備一張去背圖與錨點設定」在這裡不用——第十一輪起單品圖就是程式把款式圖打光畫出來的（`garments/render.js`），穿搭卡已經把三件疊成人形；試穿間只是把「換哪一件」交給使用者。所以範圍不是 10–20 件，是所有畫得出來的外層、上身、下身。
- **換件用一句話**：和一句話列同一個元件（`ClausePicker`）、同一種讀法。做成下拉格而不是縮圖牆，是因為這一頁的主角是人形，右邊只要能快速換件；想看縮圖去穿搭頁或單品頁。
- **狀態在網址**：`?outer=101:oat&top=102:ivory&bottom=103:ink`，貼給人就是同一套；用 `replace` 寫、不塞瀏覽紀錄。本機另記一份，單品頁的「放進試穿間」才接得上上一套。
- **人形依身形縮放只是示意**：高矮照身高（±10%）、胖瘦照體重／身高的比（−12%～+18%），畫面上寫「只是示意」。真的版型縮放要有每件的版型資料，不在試做範圍。
- **尺寸可以不選**：試穿間的重點是搭，尺寸到購物車再補（購物車本來就會提醒缺尺寸）；想在這裡選也可以。
- **入口三個**：穿搭頁、單品頁、頂欄「全部穿搭」預覽裡的「試穿間」，頁尾「找單品」欄也有。不放進頂欄五個圖示——圖示已經滿了。

## 逐檔

- `src/views/FittingView.vue`（新）：載目錄（有款式圖、類別是外層／上身／下身的單品）；起始狀態的順序：網址的三層 → `?from=穿搭` 每層取第一件 → 本機上一次 → 預設（第一件上衣、第一件下身、不穿外層）；每層都驗過（商品要在目錄裡、顏色要是它有的）。`pieces` 組成和展開穿搭同形的單品給 `OutfitLook`；換件換色用 `ClausePicker`，整句重排走 GSAP Flip；`sync` 寫網址與本機；網址被外面改也跟。人形縮放、整套加入購物車（飛向購物車）、複製網址。
- `src/fitting/link.js`（新）：本機那一份的讀寫與「放進試穿間」的查詢字串（換掉那一層、其他沿用）。

- `src/views/ProductView.vue`：畫得出來的三類多「放進試穿間」（帶目前的顏色）。
- `src/components/peeks/RoutesPeek.vue`、`src/components/SiteFooter.vue`：入口。
- `src/router/index.js`：`/fitting` 從佔位換成真的頁面（探索區，不必登入）。
- `scripts/expand-check.mjs`：新段（下面）。契約不用改：試穿間純前端。

## 容易錯的地方

- **網址帶不認得的東西**（商品不存在、類別不對、顏色不是它的）：那一層退回預設；必填的層一定有東西。
- **外層是連身裙**：`OutfitLook` 本來就會把下身藏起來；試穿間照樣讓人選下身，只是看不到——這是既有行為，先不改。
- **localStorage 不能用**：只有網址記得；「放進試穿間」就只帶那一層。
- **人形縮放**：用 `transform`，不影響版面；減少動態時不過渡。
- **減少動態**：Flip 不跑、淡入淡出被 base.css 歸零。

## 實測了什麼

- `expand-check` 新段 17 項（桌機 1252×699 合計 201／201；手機 390×844 合計 191／191）。流程：登出、訪客塞一個身形（190／90）→ `/fitting?from=1` 帶進穿搭 1（三層各一件、三張圖、網址換成三層、句子含每件的名字、總價等於三件相加、人形有縮放且說「略為縮放」）→ 上身的清單列出全部畫得出來的上衣、選第二件 → 網址 `top=104:…`、那一層只剩一張、是 104、看得見 → 外層選「不穿外層」→ 網址沒有 outer、沒有外層的圖、那一格讀「不穿外層」而不是「外層穿」→ 穿回第一件外層 → 顏色清單有色票、選第二色 → 網址帶那個色、圖變了、那一層只剩一張 → 同一個網址重新整理三層一樣、本機 `fitting` 和網址一致、沒有溢出 → 整套加入購物車 → 購物車多 3 件、「已加入 3 件」→ 單品頁「放進試穿間」帶 `outer=101:oat` 且沿用其他層 → 穿搭頁「拿這套去試穿間改」是 `/fitting?from=1`。
- `shop-check` 60／60、`member-check` 41／41，桌機與手機；`check:contrast` 42 組（沒有新顏色）；改動的文字檔無 BOM、無 CR。
- 第一次跑抓到：「換上身後圖沒變」——其實 102 圓領細針織上衣和 104 寬版棉質襯衫是同款式（kind 都是 top）、同布料、同一個米白，程式畫出來一模一樣，比圖本來就比不出；而我第一版比的還是 data URL 的前 48 字（PNG 檔頭，每張都一樣）。改成在圖層上標 `data-product`，驗收查「那一層只剩一張、是指定的那件、看得見（opacity 1）」——這一項同時證明淡出的舊圖有被拿掉。另外一次跑有六項既有段落（鍵盤選格、頂欄預覽）變紅，是我改檔中途 Vite 整頁重載打斷的，之後全程不動原始碼重跑全綠。
- 在內建瀏覽器裡換件時看到過渡卡住（舊的 opacity 1、新的 0、`-from`／`-active` 類別一直在）：那是內建瀏覽器餓死 rAF（memory 有記），無頭 Chrome 與驗收都正常；正式的瀏覽器沒驗。
- 截圖看過（`docs/r16-shots/`、`…/phone/`）：`fitting`（帶進穿搭 1）、`fitting-changed`（炭灰大衣＋寬版棉質襯衫）。
