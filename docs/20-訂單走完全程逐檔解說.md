# 20　第十七輪・子輪 1：訂單走完全程

2026-10-10。規格在 [19](19-訂單全程與強韌化-規格.md) §3。功能規劃 4 的「訂單狀態只能照狀態機走」「付款逾時自動取消」「確認收貨」都是 `必`，但第十六輪結束時假 API 只會走 待付款→已付款、待付款→已取消、已送達→完成：已付款的訂單永遠停在已付款，確認收貨只能靠一張種子訂單示範一次。自主探索的第四個子輪，設計沒有一項經過確認。

## 做了什麼（一句話）

訂單現在會走完：待付款（有付款期限、可以在訂單頁付）→ 已付款 → 出貨中 → 已送達 → 完成（確認收貨，或 7 天後自動）；逾時沒付的自動取消。訂單頁的進度是一條時間線，訂單紀錄可以依狀態篩。完成之後接回站裡的功能：更新身形、把這幾件帶去試穿間。

## 設計怎麼定的

- **物流用示範的時間比例，而且畫面上寫明**：真的出貨要幾天，發表現場看不到；假 API 用「付款 2 分鐘後出貨、5 分鐘後送達」（`DEMO_LOGISTICS`），訂單頁的進度底下有一行「出貨與送達目前是示範用的模擬……正式版由後台更新狀態」。原則還是「假的要說是假的」。正式版這兩步是後台操作，後端不用做這個比例。
- **結算時間用「應該發生的那一刻」**：出貨的時間記付款＋2 分，不是打開頁面那一刻；所以隔多久打開看到的進度都一樣，落後兩步也一次補齊（驗收有量：出貨 − 付款 ＝ 120000 毫秒、送達 − 付款 ＝ 300000）。
- **付款期限由後端算、前台只顯示**：契約 §8 多 `payBy`；前台倒數每 30 秒重算，到期就重讀一次訂單（假 API 會結算成已取消；正式版是後端排程）。15 分鐘是功能規劃 v1.3 的建議值，上網找不到蝦皮或 momo 的官方規則（規格 §1）。
- **貨到付款是四步**：狀態機原圖沒有畫貨到付款；送達前本來就沒付款，所以提案 `待付款（不逾時）→ 出貨中 → 已送達（記付款）→ 完成`，少「已付款」一步；寫進契約給 10/12 確認。
- **完成之後不是結束**：功能規劃說確認收貨後提示發穿搭照；穿搭牆藏著，所以接「更新身形」（合不合身是尺寸建議的資料）和「拿這幾件去試穿間搭別的」（帶畫得出來的外層／上身／下身、每類第一件）。
- **種子訂單的時間改成相對的**：`members.json` 的日期是寫死的，有了時間規則第一次讀就會一張逾時取消、一張自動完成。所以把兩張種子的時間整體平移到「現在」附近（`SEED_ANCHOR` 對齊現在），資料庫記 `seedVersion: 2`，舊版本的 localStorage 只重排這兩張、使用者自己下的不動。訂單編號裡的日期不改（它只是編號）。示範的故事會隨時間老去（待付款那張 15 分鐘後就逾時），發表前清掉 `account` 就回到起點（README 有寫）。
- **狀態小標分調子但不靠顏色**：待付款、進行中、完成、取消四種底色，文字永遠在；新顏色進 `tokens.css`（`--tone-wait`、`--tone-done`），對比度量尺多量了它們。

## 容易錯的地方

- **結算只在讀的時候發生**：沒人打開訂單，localStorage 裡的狀態就不會變；畫面看到的永遠是結算過的。正式版的後端排程沒有這個問題。
- **倒數到期那一刻**：前台只重讀一次（`expiredHandled`），避免每 30 秒重讀；重讀後狀態是已取消、按鈕消失。
- **舊資料的 `cancelReason`**：第十輪的已取消訂單沒有這個欄位，`publicOrder` 補成 `member`。
- **貨到付款不逾時**：`settleOrder` 第一個判斷就排除 `cod`，不然會把貨到付款的訂單取消。
- **時間線的 key 是狀態名**：同一個狀態不會出現兩次（狀態機不回頭），所以可以。

## 實測了什麼

- `member-check` 從 41 項長到 **61 項**，桌機 1252×699 與手機 390×844 全過，主控台沒有錯誤或警告。流程：種子的待付款訂單 → 列表有付款期限、篩選「全部 2」→ 明細有期限與「去付款」、時間線五步只有待付款是目前的 → 沒選付款方式就按「付款」→ 行內錯誤 → 選模擬付款 → 已付款、一步走過 → 把付款時間改成 6 分鐘前（直接改 localStorage）重新整理 → 已送達、三步走過、出貨與送達的時間差正好 2 分與 5 分 → 確認收貨要先確認 → 完成、四步走過、有「更新身形」與帶 `outer=509` 的試穿間連結 → 種子的已送達訂單確認收貨 → 結帳（模擬付款）照舊 → 再結一張貨到付款 → 完成頁寫貨到付款、沒有「去付款」→ 明細沒有期限、時間線四步 → 取消要先確認 → 已取消（自行取消）、沒有「還沒到」的步 → 塞一張 16 分鐘前的待付款信用卡訂單 → 列表讀到就是已取消 → 明細寫付款逾時、取消時間 ＝ 下單＋15 分 → `?status=cancelled` 只剩兩張 → 「全部」五張且清掉查詢字串。
- `shop-check` 60／60（桌機）、`expand-check` 201／201（桌機）：這一輪沒動的部分沒退。`check:contrast` 55 組合格。改動的文字檔無 BOM、無 CR。
- 截圖看過：`orders`（篩選列與小標）、`order-pending`（期限與兩個按鈕）、`order-delivered`、`order-done`、`order-cancelled`（時間線三種狀態），桌機與手機。

## 沒有驗證

- 使用者會不會覺得 2 分鐘／5 分鐘的示範比例太快或太慢（發表現場走一遍大概 6 分鐘）。
- 正式版後端排程與前台倒數之間的時間差（後端的「現在」和瀏覽器的不同；`payBy` 是後端算的，差幾秒前台會多顯示一下「不到 1 分鐘」）。
- 讀屏讀時間線的順序；手機實機。
