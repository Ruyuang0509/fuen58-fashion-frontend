# 25　第十八輪・子輪 1：一般模式的切換、10/12 的對照表

2026-10-10。規格在 [24](24-一般模式搜尋建議折扣碼-規格.md) §3。功能規劃 1.1「一般模式：畫面上固定有切換鍵，可改用普通首頁；記住使用者的選擇」是 `必`，之前只有「沒有 WebGL 自動退回」和「跟系統的減少動態」，使用者自己選不了。另外整理了一張對照表給 10/12 用（[23](23-功能現況對照表-給1012確認用.md)）。自主探索的第七個子輪，設計沒有一項經過確認。

## 做了什麼（一句話）

頁尾「關於」下面多一列「畫面：自動（跟系統）／減少動態／一般模式（不用 WebGL）」，記在本機，選了整頁重載；減少動態＝全站過渡與動畫歸零、GSAP 不跑、天空只畫一張；一般模式再加上不碰 WebGL（天空是 CSS 漸層）。

## 設計怎麼定的

- **三段而不是兩段**：規劃說的「一般模式」是不靠 3D；「減少動態」是另一件事（系統設定也有）。兩個合成一個選單，自動那一項會寫出系統目前的狀態，使用者才知道「自動」現在等於什麼。
- **選了就重載**：很多元件在掛載時就把「要不要動」記成常數（`const reduced = reducedMotion()`），熱切換要每個元件都改成響應式，划不來也容易漏；整頁重載最誠實，選單旁寫了。
- **一個來源**：`reducedMotion()`（GSAP 那邊）、`useFlyToCart`、頁尾「回到最上面」以前各自問 `matchMedia`，現在都問 `stores/motion.js` 的 `isReduced()`——系統設定或使用者選的都算。CSS 那邊是全域規則 `html.reduce-motion *`（和 `prefers-reduced-motion` 那段同一套）。
- **元件裡各自的 `@media (prefers-reduced-motion)`** 只管系統設定：它們做的事（關過渡、`transition: none`）全域規則都蓋到了；少數「減少動態時換一種排法」的（例如穿搭卡的 hover）在使用者選的模式下不換，差別很小，記在這裡。
- **一般模式的天空**：`createSky(canvas, { plain: true })` 直接走第十一輪就有的「沒有 WebGL」那條（CSS 漸層，顏色仍跟時間與天氣走）。畫布標 `data-sky`、`data-motion` 給驗收用。
- **對照表**：規劃的每一項對「有／半／無／後端／等」、在哪個網址或哪份解說、要全組確認的事；最後把前台自己定的全列一次。它是給組員看的，不是給程式用的。

## 容易錯的地方

- **`main.js` 的 import 順序**：`stores/motion` 要在最前面，`<html>` 的 class 才會在第一次繪製前掛上；晚了會先畫一幀有動畫的。
- **`isReduced()` 不是常數**：模式改了會重載，所以在元件裡存成常數沒關係；但不要在模組最外層呼叫一次就存起來——系統設定可以在頁面開著時改。
- **`plain` 只影響天空**：其他 WebGL（`/lab/cloth` 的 three.js 試做）不在正式導覽裡，沒處理。
- **驗收的探針**：行內 `transition: opacity 1s` 的元素，全域 `!important` 規則蓋得過行內樣式，算出來是 `0s`；正控在自動模式下是 `1s`。
