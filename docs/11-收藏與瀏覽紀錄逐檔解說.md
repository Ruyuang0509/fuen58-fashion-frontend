# 11　第十五輪・子輪 2：收藏、瀏覽紀錄、會員中心分頁列

2026-10-06。規格在 [09](09-內容與功能拓展-規格.md) §3；使用者說「開工吧」，另裁示「登入憑證放哪」交給後端（契約「還沒定的」第 5 點列了兩種做法的取捨；子輪 4 後那一節是 §12）。

## 做了什麼（一句話）

單品和整套穿搭都能收藏，訪客不用登入（存在這個瀏覽器），登入或註冊時併進帳號；看過的單品與穿搭留在本機的「你看過的」；頂欄多一顆帶件數的愛心，按收藏時有一顆小愛心飛過去；會員中心從三個文字連結變成帶圖示的五格分頁列。

## 逐檔

### 資料與狀態

- `src/stores/favorites.js`（新）：整站只有一份「現在這個人的收藏」。訪客讀寫 localStorage 的 `favorites`；`watch(loggedIn)`——登入狀態一變就重新對齊：登出讀本機；登入時本機有東西就送 `mergeFavorites`（聯集、同一件保留較早的時間），沒有就 `getFavorites`，併完清掉本機。`toggle(kind, id, { colour })` 先改畫面再通知帳號，失敗不回滾（下次同步會對齊）。它不被 `session.js` 引用（避免循環），是它去 watch 登入狀態。
- `src/stores/history.js`（新）：`record(kind, id)`、`clear()`；單品與穿搭各最多 24 筆，重看移到最前；只在 localStorage 的 `history`，**不進後端**。
- `src/api/account.js`：會員物件多 `favorites: { products: [{ productId, colour, addedAt }], outfits: [{ outfitId, addedAt }] }`；`getFavorites`、`addFavorite`、`removeFavorite`、`mergeFavorites`。`publicUser` 不再回傳 `favorites`（登入狀態存的是會員資料的快照，收藏一直在變，走自己的端點）。契約 §10。

### 愛心

- `src/components/FavButton.vue`（新）：全站同一顆。真的 `<button aria-pressed>`；收起來是描邊、收藏後填滿換強調色、按下去跳一下（`popping` 只在按的那 0.45 秒加，已收藏的在載入時不跳）；有文字版（「收藏這套」→「已收藏」）與只有圖示的圓版（讀屏唸「收藏：名稱」）。
- `src/composables/useFlyToCart.js`：抽成通用的 `flyTo(source, { target, event, duration, endScale, colour })`；`fly(image)` 照舊飛向購物車，新的 `flyHeart(icon)` 把一顆填滿的心沿同一條弧飛向頂欄的收藏（0.8 秒、留到六成），到站送 `fav:arrive`。
- `src/components/Icon.vue`：加 `heart`、`clock`、`pin`。
- `src/components/ProductCard.vue`：**根元素從 `<a>` 改成 `<article>`**——按鈕不能放在連結裡。圖和名稱各自連到商品頁；愛心在圖的右上角，滑過卡片才出現、已收藏的一直在、觸控裝置一直在（`@media (hover: none)`）。驗收腳本裡原本用 `a.href` 量的地方改成找卡片裡的連結。
- `src/components/OutfitCard.vue`、`src/views/OutfitView.vue`：動作列多「收藏這套」。
- `src/views/ProductView.vue`：購買區塊「加入購物車」旁多一顆愛心（記下現在看的顏色）。
- `src/components/SiteHeader.vue`：第五個圖示「收藏」帶件數（和購物車同一種標法），`fav:arrive` 時接一下；在收藏頁上心是填滿的。手機上五個圖示要和站名擠同一列：圖示間距再緊一點，天氣小圖示在 36rem 以下收起來（390 寬量過一列放得下）。

### 頁面

- `src/views/FavoritesView.vue`（新）`/favorites`，交易區、不需登入：「單品」每列有款式圖（收藏時看的顏色）、名稱、品牌・顏色、價格、尺寸下拉（無庫存的不能選）、加入購物車（沒選尺寸就在旁邊說「請先選尺寸。」）、移除；「穿搭」直接用穿搭卡。訪客會看到「現在存在這個瀏覽器；登入後會併進你的帳號」。空狀態一句話加「看全部穿搭」。
- `src/views/HistoryView.vue`（新）`/history`「你看過的」：單品一格、穿搭一段、右上「清除紀錄」。
- `src/components/RecentlyViewed.vue`（新）：商品頁底部一排最近看過的單品、穿搭頁底部一排最近看過的穿搭；排除正在看的、最多 8；沒有紀錄整段不出現。
- `src/components/AccountNav.vue`：五格帶圖示的分頁列（個人資料、地址簿、訂單紀錄、收藏、看過的），目前所在的那格有框有底；手機橫向可捲。規格原本寫七項，「我的偏好」等子輪 4 做出來再加，「身形資料」沒排進時程就不放連到佔位畫面的連結。
- `src/router/index.js`：`/favorites`、`/history`；`/account/favorites` 轉到 `/favorites`。
- `src/components/SiteFooter.vue`：會員欄多「收藏」「看過的」。

### 驗收與文件

- `scripts/expand-check.mjs` 第二段 26 項：訪客收藏單品（心亮、頂欄 1、本機存了顏色）→ 收藏一套穿搭（頂欄 2）→ 收藏頁一列一卡、沒選尺寸的錯誤、選 M 加入購物車 → 登入 demo → 頂欄仍 2、本機清空、帳號裡各一 → 分頁列五格 → 商品頁的心是亮的、再按一次變 1 → 看過 201 與 101 後商品頁「最近看過」有 201 沒有 101 → 進一套穿搭 → 「你看過的」3 件 1 套、最新的在前 → 清除 → 空狀態 → 頂欄五個圖示在視窗內。
- `scripts/shop-check.mjs` 頂欄連結多「收藏」；`scripts/member-check.mjs` 分頁列 3 → 5。
- `docs/api-契約草案.md`：§10 收藏五個端點與兩張表、瀏覽紀錄不進後端；「還沒定的」加登入憑證兩種做法（子輪 4 後是 §12）。

## 實測了什麼

- `npm run build` 成功；`expand-check` 73／73、`shop-check` 60／60、`member-check` 39／39，三支都在 1252×699 與 390×844 跑（溢出檢查是上一子輪修正過的那個）；無頭 Chrome 沒有主控台錯誤。
- 截圖看過：收藏頁（桌機、手機）、你看過的（分頁列、三件）、穿搭卡滑過時的「收藏這套」、商品頁按下愛心 350 ms 那一刻、手機商品頁底部的「最近看過」、手機穿搭頁的「收藏這套」。
- **沒有驗證**：使用者本人；手機實機（五個圖示一列是量出來的，不是摸出來的）；讀屏唸 `aria-pressed` 的效果；小愛心飛行的手感。
