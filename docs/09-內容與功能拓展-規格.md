# 09　內容與功能拓展：規格與執行計畫（2026-10-06）

這份是第十五輪起四個子輪的規格。使用者 2026-10-06 提出六項（瀏覽紀錄、喜愛項目、使用者喜好推測、註冊後偏好調查、活動與廣告位與新品置入、多重篩選），貼了 daytona-park.com 的頁尾當參考，說它功能齊全值得參考、但要以更美的方式重現，UI 可以再大改；footer 是上一輪的待辦。Claude 提了拆法與九個裁決點，使用者回「以上項目全部允許你自主判斷」——所以**以下每一條都是 Claude 的決定**，可改。

## 0. 參考站看到什麼（觀察）

daytona-park.com，2026-10-06 用內建瀏覽器看了首頁、上裝列表、一個商品頁。

- 首頁：公告 → 店鋪清單 → FOR YOU 推薦 → 每日排行榜 → 新品 → 活動（一檔活動配一排商品）→ 員工精選 → 直播、雜誌、使用者穿搭（接 Instagram）→ 品牌精選 → 類別清單 → 六欄 sitemap 頁尾。
- 列表：左側「篩選條件追加」鈕＋關鍵字；上方「全部／原價／折扣」、「組合顏色」、排序預設「推薦順」；卡片有「新的」「預訂」標籤。**沒打開它的篩選面板**，多選怎麼做沒驗證。
- 商品頁：每個顏色 × 尺寸一列、各有庫存與加入購物車；分頁籤「說明／尺寸與材質／顧客評價／員工評價」；員工評價有五條刻度（厚薄、光澤、透膚、重量、彈性）加員工身高；用這件的穿搭（帶身高）；相關文章；相關商品；FOR YOU；品牌排行；類別排行；閲覧履歴；類別清單。
- 列表頁有一個「顯示推薦」對話框，附說明「輸入的資料只用於尺寸指南、重排推薦、篩選候選商品，只存在這台裝置，180 天自動刪除」——偏好調查的近親（沒點進去，問什麼是推測）。

它的強項是商品頁的橫向探索與「現在店裡在發生什麼」（排行、新品、活動）；我們最弱的也正是這兩處。

## 1. 原則

1. **功能追齊，語彙不變**：天空、一句話、以穿搭為單位、不規則格、細線圖示——探索區骨架不翻；更動集中在新長出來的面（首頁下半、單品列表、商品頁下半、會員中心、頁尾）。
2. **交易區不放推廣**：購物車、結帳、登入、會員頁沒有活動、沒有推薦。
3. **規則式、看得懂**：推測全是加權規則，不稱 AI；每一處推薦都寫一句理由。
4. **訪客也能用**：收藏、瀏覽紀錄不逼登入；登入時併入帳號。
5. **假資料先行，契約同步**：每個子輪更新 `docs/api-契約草案.md`；三個規劃裡沒有的項目（活動、瀏覽紀錄、多選）標「10/12 待全組確認」。
6. **文案不捏造數字**：假活動不寫「銷量突破 N 件」；排行用假資料的 `sold` 排序，但不把數字當事實宣傳。

## 4. 子輪 3：多選篩選、單品列表

### 4.1 一句話列的多選

- `ClausePicker.vue` 取代原生 `<select>`：一顆按鈕顯示現在的片語，點開是勾選清單（`role="listbox"`、`aria-multiselectable`、方向鍵移動、空白鍵或 Enter 勾選、Esc 關、點外面關）；手機（≤ 36rem）變成底部面板。片語：沒選 → 該格的「不限」說法；一個 → 它；兩個 → 「A 或 B」；三個以上 → 「A、B 或 C」。
- 多選的格：場合、類別、尺寸（子輪 3 一起做的單品列表再加品牌、顏色）。**風格維持單選**——它是路徑、也是天空的時刻；給誰穿單選（語意已含中性）。
- 網址逗號分隔：`?occasion=work,date`。`useFilters` 的 `MULTI = ['occasion', 'category', 'size']`，值是陣列；不認得的值丟掉、重複去掉。
- `getOutfits`：場合「任一符合」；類別「任一件屬於任一類」；尺寸「候選單品任一件有任一尺寸」。
- Flip 位置改在 `ClausePicker` 開啟前記（它會發 `open` 事件）。

### 4.2 單品列表 `/products`（`ProductsView.vue`，取代 `SearchView.vue`；`/search` 轉址到 `/products` 並保留查詢字串）

句子：「找〔全部單品｜外套〕，〔不限品牌｜霧岸或半日〕的，〔不限顏色｜灰或駝〕色，〔不限價格｜兩千以內〕，尺寸〔不限｜M〕，〔有貨沒貨都看｜只看有貨〕，照〔新上架〕排，共 N 件。」有關鍵字時句首多「『關鍵字』」。

- 查詢字串：`q, category, brand, colour, price, size, stock, sort`；多選逗號分隔。
- 價格三檔預設：`lt2000` 兩千以內、`2000-4000` 兩千到四千、`gt4000` 四千以上（句子裡讀得順；滑桿塞不進句子）。
- 顏色是「色系」不是商品各自的色名：`src/products/colourFamily.js` 的 `familyOf(hex)` → 黑、白、灰、米駝、棕、藍、綠、紅、黃、粉、紫（HSL 門檻：L < 0.14 黑；L > 0.9 且 S < 0.15 白；S < 0.12 灰；色相分桶，其中 25–55° 且 S < 0.35 且 L > 0.55 米駝、15–45° 且 L < 0.55 棕）。清單裡以色點顯示。
- 尺寸選項：S、M、L、XL、F（單一尺寸）、110、120、130。
- `getProducts` 擴成 `{ q, category, brands, colours, sizes, priceMin, priceMax, inStock, sort, ids, theme, brand, exclude }`；`searchProducts` 保留為薄包裝。頂欄搜尋送到 `/products?q=`。
- 契約 4.2 的查詢字串改成多值逗號分隔，加 `colour`（色系代碼）。

### 4.3 驗收

`/outfits?occasion=work,date` 的套數 = 場合含上班或約會的套數，句子顯示「上班或約會」；`/products?brand=wuan,banri` 13 件；`/products?colour=black` 件數 = 任一顏色屬黑的商品數（腳本用同一個 `familyOf` 算）；`/products?price=lt2000` 全部 < 2000；鍵盤 Tab 到格、Enter 開、方向鍵、空白鍵勾、Esc 關；390 寬是底部面板；`/search?q=大衣` 轉到 `/products?q=大衣` 且結果同前；既有檢查不退。

## 5. 子輪 4：偏好調查、推測、為你排

### 5.1 調查 `/onboarding/style`（註冊成功後進入，帶 `redirect`；每一步都能略過）

1. 給誰穿：四顆大鈕＋「先不選」。
2. 挑至少三套你會穿的：一開始 8 套人形（各路線至少一套）；每挑一套，從相鄰路線補進最多兩套還沒出現的（Flip 重排）。相鄰表 `THEME_NEIGHBOURS`：minimal↔formal、vintage；street↔punk、outdoor；vintage↔minimal、lolita；outdoor↔street、minimal；formal↔minimal、vintage；punk↔street、vintage；lolita↔ryousan、vintage；ryousan↔lolita、street。不足三套時按鈕停用並提示。
3. 結果：**風格組成比例**——一條用路線色拼成的橫條與「40% 街頭・30% 復古・30% 簡約」（功能規劃 6.3 借 Stitch Fix 的呈現）；「開始逛」回 `redirect`，「重新挑」回第 2 步。
- 存法：會員 `preferences: { audience, themes: { code: weight }, pickedOutfitIds, updatedAt }`，權重 = 各路線被挑套數 ÷ 總數（兩位小數、總和 1）。契約 `GET/PUT /api/me/preferences`。`/account/style` 顯示同一條橫條與「重新挑」。登入不觸發調查，只有註冊會。

### 5.2 推測 `src/taste/profile.js`

`buildProfile({ preferences, favorites, history, outfitsById, productsById })` → `{ weights, top, reasons: [{ code, text }], source }`。訊號與權重：調查 1.0；收藏穿搭 +0.6／套、收藏單品 +0.6 平分給它所屬的路線；看過的穿搭 +0.2／套、單品 +0.2 平分。加總後正規化。理由取每條路線最強的訊號：「你挑了 3 套街頭」「你收藏了 2 件復古」「你最近看了 4 套戶外」。沒有任何訊號 → `null`。

### 5.3 用在哪

- `/outfits` 與首頁的店：沒選風格且有 profile 時，穿搭照路線權重排（同權重照 id）；標題後多一格「，照你的喜好排（關）」，關掉記在 localStorage `forYou=0`；標題下一行理由。
- 商品頁「你可能也想看」：首選路線（不足再第二）的單品，排除自己，前 6，附理由。

## 7. 容易出錯的輸入（每個子輪的檢查都要碰到）

1. localStorage 不能用（隱私模式、滿了）：收藏、紀錄、為你排的開關全部退到記憶體，頁面不壞（沿用 cart.js 的寫法）。
2. 收藏裡的商品已經不在目錄：顯示時跳過，不當機；合併時同 id 不重複。
3. 網址帶不認得的值（`?occasion=foo`、`?size=M,M`、`?price=abc`）：丟掉、去重，句子顯示「不限」。
4. 活動的日期：`endsAt` 含當天、臺北時區；過期的在舞台與頁尾消失、活動頁照開並標示結束；活動沒有穿搭時店顯示空狀態而不是載入中。
5. GitHub Pages 的子路徑：站內連結一律 `RouterLink`；只有 GitHub 是絕對網址。
6. 空狀態：收藏空、紀錄空、調查不足三套、單品列表零件（給同路線的單品，和搜尋無結果同一套）。
7. 單品卡根元素改成 `<article>` 後，整張卡仍要能點（連結蓋住圖與名稱），愛心在連結之外。
