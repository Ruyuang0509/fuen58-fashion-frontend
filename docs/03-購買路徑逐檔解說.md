2026-10-06，第九輪。使用者說「再讓你繼續自由開發一輪，追加功能或更動設計佈局都允許」。
我選了**把購買路徑做出來**：商品頁、購物車、搜尋結果，三頁在功能規劃裡都是「必」，到上一輪為止都還是佔位畫面；

## 資料

### `src/api/mock/products.json`、`scripts/gen-products.py`

商品的細節，一件一筆，用 `productId` 和穿搭裡的單品對起來。穿搭（`outfits.json`）裡的單品只有列表要用的欄位（名稱、品牌、類別、價格、尺寸、款式、布色）；
商品頁才要的放這裡：

| 欄位 | 內容 | 怎麼來的 |
|---|---|---|
| `kind`、`fabric` | 款式圖代碼、布料（給渲染用） | 手寫；襪子、皮帶這輪補了款式圖 |
| `material` | 材質成分的字 | 手寫 |
| `description` | 一句話描述 | 手寫，32 件各一句，寫的是版型、長度、布料手感這類具體的事，不寫形容詞 |
| `warmth`、`features` | 厚薄等級 1–5、機能標籤（防潑水、快乾） | 手寫 |
| `colours` | 顏色清單 `{ code, name, hex }`，第一個是預設色，hex 等於穿搭裡的布色，所以穿搭的樣子不變 | 手寫 |
| `stock` | 顏色 × 尺寸 → 庫存件數，key 是 `顏色code-尺寸` | 規則：固定亂數種子 4–18 件，另外指定了 7 格是 0（讓第一套穿搭就看得到「無庫存」）、4 格是 1–3 件（看得到「還有 N 件」） |
| `measure` | 尺寸表：`columns` 欄名、`rows` 每個尺寸一列 | 規則：每種款式一組基準值與級距（外套 肩寬 48 起每級加 2……），再加每件的調整（寬版襯衫更寬、短袖的袖長短 34） |
| `fit` | 模特兒身高、體重、穿的尺寸、一句穿感 | 手寫 |
| `tags` | 搜尋用的標籤 | 手寫 |

這些資料由 `scripts/gen-products.py` 產生（手寫的部分就寫在腳本裡），改資料改腳本重跑，不要直接改 JSON：

```bash
python scripts/gen-products.py
```

**哪些數字是我暫定的、要全組決定**：庫存的分布、尺寸表的基準值、厚薄等級的溫度對照（`labels.js`）、運費 80 元滿 2,000 免運（`labels.js`）。
功能規劃 3.1 說「顏色 × 尺寸為一個規格，各有價格與庫存」——這裡顏色之間同價，只有庫存分開；如果後端要做到各色不同價，`price` 要搬進 `colours` 裡。

### `src/api/index.js`

多了四個函式；畫面只呼叫它們，之後換成 `fetch` 畫面不用改：

- `getProduct(id)`：一件商品的完整資料 = 穿搭裡那件單品的列表欄位 + `products.json` 的細節 + `themeCodes`（它出現在哪些主題的穿搭裡）。找不到回 `null`。
- `getProducts({ ids, theme, exclude })`：多件。購物車用 `ids`，同路線推薦用 `theme` 加 `exclude`。
- `getOutfitsWithProduct(id)`：包含這件的穿搭。
- `searchProducts(keyword)`：空白分開的每個詞都要命中名稱、品牌、標籤或所屬主題名稱之一；不分大小寫。

`productOf()` 那段就是後端將來的 join（商品表 ⨝ 穿搭單品表）。這裡把它寫在前端，是因為後端現在還沒有「穿搭組合」這張表（01 第 5 節提過），要先跟組員對。

### `src/products/labels.js`

資料在畫面上的說法：厚薄等級 → 「偏厚，適合 6°–16°」；類別代碼 → 名稱；運費規則；金額格式（`NT$ 3,280`）。
厚薄對照表功能規劃 5 說以後由後台的「天氣規則管理」維護，所以獨立成一個檔，之後改成從 API 來。

## 商品頁：`src/views/ProductView.vue`

上半部兩欄（7:5）。左邊是圖，右邊是說明與購買區塊；下面兩段是「這件出現在的穿搭」與「同路線的其他單品」。窄螢幕（≤ 56rem）變一欄。

**探索區的部分**（看錯沒有代價）：

- 大圖點了放大：用原生 `<dialog>`，Esc 會關、點暗處會關；圖以視窗為限（高不超過 86vh）。
- 每個顏色一張小圖，點了換色。**顏色寫在網址（`?colour=charcoal`）**：貼連結給人看到的是同一個顏色，和「篩選條件只存在網址裡」是同一個原則。尺寸與數量不寫進網址，那是交易的細節。
- 「走 簡約 路線」連到主題頁；品牌連到品牌頁（還是佔位）。
- 「這件出現在的穿搭」用 `OutfitLook` 畫，點了去那套穿搭的主題頁——**因為還沒有穿搭頁**，見最後「還沒決定的事」。

**購買區塊**（守慣例，介面方向筆記 2.2 的五條怎麼落實）：

1. 位置符合預期：一個畫面只有一個主按鈕（加入購物車），放在區塊最下面；價格在名稱正下方。
2. 標準表單：顏色與尺寸是真的 `<input type="radio">`（圓點藏起來、用外框表示選到），`<fieldset>` 加 `<legend>` 當看得見的標籤；鍵盤可以走完全程。沒選尺寸就按「加入」：錯誤訊息「請先選尺寸。」貼在尺寸欄位下面（`role="alert"`），焦點移到第一個可選的尺寸；不跳視窗。
3. 數字一眼可讀：價格、數量、庫存都是立刻更新的文字，沒有動畫；數字用 Space Mono。
4. 可以回頭：換顏色後，原本選的尺寸在新顏色沒貨，就取消選擇讓人重選，不會偷偷換成別的尺寸。
5. 動畫只做回饋：按下「加入」後，大圖縮小飛向頂欄的「購物車」（`useFlyToCart`），件數跳一下；不擋操作、系統設定減少動態時不做。

其他：

- **無庫存的尺寸不可選**（功能規劃 3.3 必）：按鈕變虛線框、字劃掉、底下寫「無庫存」，`<input disabled>`。
- **試穿資訊放在尺寸旁邊**（功能規劃 3.3 必、v1.3）：「模特兒 170 cm／56 kg，穿 M：肩線落在肩點外約 3 公分……」。
- **尺寸表**（特）：收在 `<details>` 裡，選到的尺寸那一列有底色；表尾註明平量有 1–2 公分誤差。
- **數量與庫存上限**（必）：加減按鈕與可以直接打字的數字框，上限是這個顏色這個尺寸的庫存；剩 3 件以內顯示「這個尺寸還有 N 件」。
- 單一尺寸（毛帽、襪子、皮帶）直接選好，顯示「單一尺寸」；只有一個顏色的商品顯示顏色名，不出現單選鈕。
- 商品代碼不存在：「找不到這件商品」加「看全部穿搭」。
- 從同路線推薦點到另一件：Vue Router 沿用同一個元件、只換參數，所以用 `watch(route.params.id)` 重新載入，並清掉上一件選的尺寸與數量。

## 購物車

### `src/stores/cart.js`

一列 = 同一件商品、同一個顏色、同一個尺寸；數量在 `qty`。列裡只存身分（`productId`、`colour`、`size`）和名稱價格的快照；
庫存、顏色名、尺寸選項都由購物車頁向 API 重新要——商品下架、改價、庫存變動都要以當下為準，不信購物車裡存的。

`add(item, size, colour, qty)`：`size` 為 `null` 表示還沒選、`colour` 為 `null` 表示預設色（穿搭卡「整套加入」就是這樣加的）。
另有 `setQty`、`setSize`（改完如果和另一列變成同件同色同尺寸就併成一列）、`remove`（回傳原本的位置）、`restore`（復原到原位）、`subtotal`。
舊版本存的列沒有 `colour` 欄位，讀出來時補成 `null`。

### `src/views/CartView.vue`

交易區的置中單欄（38rem）。從上到下：

- **桿子**：一條粗線，底下掛著購物車裡每一件（`aria-hidden`，純意象，功能規劃 4「以衣架或衣櫃的意象排列」）。同一件買兩件就掛兩個衣架疊著（最多畫三個），右下角寫 ×N。
- **品項清單**：小圖、名稱（連回商品頁、帶著顏色）、品牌與顏色、尺寸、單價、數量、小計、移除。
  - **尺寸沒選的列**：下拉選單顯示「請選尺寸」、外框是提醒色；無庫存的尺寸在選單裡標「（無庫存）」且不可選。有尺寸的列也是同一個下拉選單，可以直接改（功能規劃 4「改規格」）。改顏色要回商品頁。
  - **庫存**：資料回來後，數量超過庫存的列調到庫存數並說明「庫存只剩 N 件，數量已調整」；完全沒庫存的說「這個尺寸目前沒有庫存，請改尺寸或移除」。加號到上限就停；直接打 99 會被調回上限。
  - **下架**：API 沒有這件商品 → 「這件商品已下架，請移除」，那一列變淡、數量不能改。
  - **移除不先問，但可以復原**：刪錯一列的代價小，每次都問反而煩；刪掉後出現「已移除「○○」。復原」六秒，復原會放回原來的位置。
- **金額**：小計、運費（滿 2,000 免運，否則 80；差多少免運會寫）、合計。數字立刻更新，沒有跳號。
- **前往結帳**：只有每一列都有尺寸、都有庫存、商品都還在才按得下去；按不下去時旁邊寫「還有 N 件沒選尺寸」。按了去 `/checkout`（還是佔位）。
- 空的購物車：「購物車是空的」加「看全部穿搭」。

## 搜尋：`src/views/SearchView.vue`

關鍵字在網址（`?q=襯衫`）。標題寫「「襯衫」，6 件單品」，底下是單品格。
沒有結果：「找不到和「zzz」有關的單品。可以換個說法，或直接看穿搭。」加一排**最近進過的那個路線**的單品（讀 `useThemeAccent` 記住的主題；沒進過就第一個主題）——功能規劃 3.2 說無結果「顯示提示與同主題推薦，不留空白」。
搜主題名稱（例如「龐克」）也會命中那個路線的單品。

`SiteHeader` 的搜尋框現在顯示網址上的關鍵字：在結果頁重新整理、按上一頁，框裡的字和結果一致。

## 實測了什麼

無頭 Chrome（CDP），1252×699 與 390×844 各跑一遍同一套腳本，52 項檢查全過，兩種寬度都沒有主控台錯誤與警告、沒有水平捲軸。檢查的事：

- 商品頁 101：圖是程式畫的 PNG；兩個顏色、三個尺寸、燕麥 S 不可選。沒選尺寸按加入 → 錯誤訊息出現、焦點在尺寸單選鈕、購物車件數還是 0。選 M、加到 2 件。換成炭灰 → 網址 `?colour=charcoal`、圖換了、圖說「炭灰」、L 變不可選、M 還是選著。按加入 → 飛出去的那張圖存在（桌機）、回饋「已加入購物車：炭灰・M × 2」、頂欄 2。放大 → `dialog[open]`，Esc 關掉；放大的圖高 601px（視窗 699）。出現在 ≥1 套穿搭、同路線 ≥1 件。尺寸表 5 欄、選到的 M 那列有標記。
- 商品頁 404（襪子）：款式圖（不是布塊）、「單一尺寸」、加入後頂欄 3。`/products/999` → 「找不到這件商品」。
- 穿搭卡整套加入三件（尺寸未選）→ 頂欄 6。
- 購物車：5 列、3 列沒尺寸、結帳按不下去、「還有 3 件沒選尺寸」、桿子 6 個衣架 5 組、小計 NT$ 12,980 免運。燕麥的選單裡 S 不可選；選 M 後仍 5 列（燕麥 M 和炭灰 M 是不同列）。米白上衣選 M（庫存 2）→ 加兩次停在 2、加號失效。全部選完 → 沒有缺尺寸、結帳可按。第一列打 99 → 調回 15（炭灰 M 的庫存）、頂欄 20。移除襪子 → 4 列、「已移除「健行襪」」；復原 → 5 列、位置還在第二列。按結帳 → `/checkout`。
- 搜尋：「襯衫」6 件、搜尋框顯示「襯衫」；「龐克」3 件；「zzz」→ 空結果文字與推薦的單品格。
- `npm run build` 成功；`npm run check:contrast` 33 組合格；新用的提醒紅 `#9b2c2c` 對卡片底 7.53、對頁面底 7.10（另外算的）。

## 還沒決定的事（要你或全組決定）

1. **穿搭有沒有自己的一頁。** 現在穿搭只是列表裡的卡與商品頁裡的一排，點了都去主題頁。如果要「一套穿搭的頁面」（大圖、每件單品、整套加入、為什麼合今天），路由和資料都要加。我的建議是要，因為站的瀏覽單位就是穿搭。
2. **商品資料的欄位要跟後端對**：`colours`（顏色 × 尺寸的庫存）、`measure`（尺寸表）、`fit`（模特兒試穿）、`warmth`／`features`（天氣標籤）、`tags`、「一件商品屬於多個主題」。這些都是功能規劃 3.1 列的，欄位名是我取的。11/2 看 DB 前要定。
3. **運費 80、滿 2,000 免運；厚薄等級的溫度對照**：暫定數字。
4. **品牌頁、結帳、登入**還是佔位；商品頁的品牌連結與購物車的「前往結帳」都通到佔位畫面。
5. **沒做的特／加項目**：尺寸推薦（6.2，要先有會員身形資料）、收藏、穿這件的人（要穿搭牆）、評價、試穿入口。
6. **顏色之間同價**：各色不同價的話資料結構要改（見「資料」一節）。
