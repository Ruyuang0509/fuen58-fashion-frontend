# 27　第十八輪・子輪 3：折扣碼

2026-10-10。規格在 [24](24-一般模式搜尋建議折扣碼-規格.md) §5。功能規劃 4「優惠券：輸入代碼折抵」是 `加`，後台 5「優惠券管理」是後端的。自主探索的第九個子輪，設計沒有一項經過確認；四個示範碼的規則是示範值。

## 做了什麼（一句話）

結帳第二步多一格「折扣碼」：輸入、套用（Enter 也行）、成功寫「折 N 元」或「免運」並可取消；金額區多「折扣」一列；訂單記 `coupon` 與 `discount`，訂單明細與完成頁跟著顯示；契約補 `couponCode`、`COUPON_INVALID` 與新 §16。

## 設計怎麼定的

- **折扣只在後端算數**：結帳頁先用 `checkCoupon` 驗給回饋（錯誤貼在欄旁：沒有這個折扣碼／已經過期／未達門檻：滿 N 元才能用）；下單時 `createOrder` 再驗一次、重算折扣、運費、合計——正式版就是後端做這件事，前台顯示的只是預覽（契約 §8 一直這樣寫）。
- **免運門檻看折扣後的小計**；免運券直接 0。這是〔本專案〕的選擇，另一種做法是看折扣前，10/12 可以一起定。
- **四個示範碼**：`WELCOME100`（滿 1,000 折 100）、`AUTUMN15`（85 折、最多折 500）、`SHIPFREE`（免運）、`SPRING2026`（已過期，用來示範錯誤）。代碼大小寫不分（輸入時轉大寫顯示）。
- **Enter 在折扣碼欄不會送出整張表單**（`@keydown.enter.prevent`），不然打完代碼按 Enter 會直接下單。
- **訂單頁的顯示**：有折扣才多一列「折扣（代碼）−N」；運費那一列免運券寫「免運（折扣碼）」，和「滿額免運」分得開。
- 沒做：一人一次、指定商品、多張疊用、後台管理（都是後端或之後的事）。

## 容易錯的地方

- **`type="search"`／大小寫**：代碼在假 API 裡統一轉大寫比對，畫面上用 `text-transform: uppercase` 顯示；存進訂單的是正規化後的代碼。
- **購物車變了折扣要重算**：結帳頁套用時用當下的小計；下單時假 API 再算一次，所以門檻變了會在下單那一刻被擋（`COUPON_INVALID` 貼在表單頂）。
- **`.summary .total` 選到的是 `dt`**：訂單明細的「合計」`dt` 和 `dd` 都帶 `total` class——驗收第一版拿到「合計」兩個字，改成 `dd.total`。這是檢查寫錯，不是產品。
- **折扣後的小計可能等於 0**（全額折）：`total` 會只剩運費；假 API 沒擋，正式版要不要允許由後端定。

## 實測了什麼

- `member-check` 68 → **74 項**，桌機 1252×699 與手機 390×844 全過：結帳第二步輸入 `NOPE` → 「沒有這個折扣碼」；`WELCOME100` 在 280 元 → 「未達門檻：滿 1,000 元才能用」；小寫 `shipfree` → 套用成功、運費寫「免運（折扣碼）」、合計 280；取消折扣 → 合計回 360、輸入框回來；再套用 → 貨到付款下單 → 完成頁「免運（折扣碼）」合計 280 → 訂單明細同樣。
- 其餘流程（訂單狀態機、取消、逾時）在同一支腳本裡沒退；改動的文字檔無 BOM、無 CR。
- 截圖：`checkout-2`（套用後的第二步，桌機與手機）。

## 沒有驗證

- 真的後端怎麼定免運門檻（折扣前或後）、一人一次、多張疊用——10/12 或 11/2 對。
- 金流沙盒接上後折扣怎麼帶給金流（金額以後端為準，這裡沒碰）。
- 使用者要不要在購物車頁就能輸入折扣碼（現在只在結帳第二步）。
