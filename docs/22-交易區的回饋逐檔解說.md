# 22　第十七輪・子輪 3：交易區的回饋——結帳轉場、下單完成的動畫

2026-10-10。規格在 [19](19-訂單全程與強韌化-規格.md) §5。功能規劃 4「購買流程的樂趣」四項裡，加入購物車會飛（第十二輪）、購物車有衣架（第九輪）早就有；剩下「結帳步驟之間有連續的轉場與進度感」「下單完成一段簡短的完成動畫，可跳過」是這一輪補的。自主探索的第六個子輪；這是視覺工作，**好不好看是使用者的判斷**，這裡只寫做了什麼、量了什麼。

## 做了什麼（一句話）

結帳的第二步從右邊滑進來（回上一步從左邊），0.32 秒；下單完成頁剛從結帳過來時，訂單裡畫得出來的衣服一件件落進一個提袋，提袋壓一下彈回，再出一行「收到了，共 N 件。」——1.2–1.6 秒，右上角「跳過」、Esc 也行；減少動態時直接出最後的畫面；重新整理不再播。

## 設計怎麼定的

- **轉場只動新的一步**：舊的一步直接拿掉、不等它離場（Vue 的 `Transition` 不用 `out-in`），所以 `nextTick` 時新標題已經在，焦點照第十輪的做法立刻移過去；滑入結束把行內樣式清掉（`clearProps`），停下來的畫面和沒轉場一樣。這是「編排交 GSAP、微互動留 CSS」的分工：進度列的「2」亮起只是 CSS 的 `transition: color`。
- **完成動畫用站裡已有的東西**：衣服是 `GarmentImage` 畫的款式圖（和穿搭卡、購物車衣架同一套），提袋是和頂欄購物車圖示同一種細線畫法的 SVG（後片、衣服、前片三層，衣服站在袋裡露出一截）。沒有生圖、沒有彩帶。
- **播完的畫面＝跳過的畫面＝沒播過的畫面**：位置全在 CSS，GSAP 只動 `transform` 與 `opacity`；結束（自然播完或 `progress(1)`）就 `clearProps: 'all'` 把行內樣式清光，剩下的是靜態版。驗收直接比對兩種結尾的 DOM 狀態。
- **只在剛下單時播**：結帳頁下單成功後在 `sessionStorage` 留 `celebrate:<訂單編號>`，完成頁讀到就播、讀完就拿掉。重新整理、從訂單紀錄回來都是靜態的。
- **可跳過、尊重減少動態**（功能規劃 §9）：「跳過」按鈕只在播放時出現；`prefers-reduced-motion` 時不建時間軸，直接 `done`。
- **文案誠實**：「收到了」是收到訂單，不是「打包好了」——還沒出貨。

照 claude-art 的量表自檢（只列檢查項，不自評分數）：L2 #1 文字對比——那一行用既有的次要文字 token 在頁面底上，`check:contrast` 裡那組合格；L2 #2 非文字對比——提袋輪廓是裝飾，不套 3:1；L3 #8 旋轉——衣服從 ±9° 轉正、0.7 秒，沒有每幀大角度；L3 #14 放開後回到靜止——結束時行內樣式清光，驗收量過；L3 #9 動態中的顏色——衣服在動態裡是同一張圖，沒有短暫出現的色塊。

## 逐檔

- `src/views/CheckoutView.vue`：`direction`、`onStepEnter`（GSAP `fromTo` x ±28 → 0、0.32 秒、`clearProps`；減少動態直接 `done()`）；兩個步驟的 `<form>` 包進 `<Transition :css="false" @enter>`；下單成功留 `celebrate:<id>` 記號。
- `src/views/OrderDoneView.vue`：提袋舞台（`.celebrate[data-state]`：idle／playing／done）、最多四件衣服（`garments`，依件數置中散開）、時間軸（落下 0.7 秒 stagger 0.12、提袋 scaleY 0.955 一下、一行字 0.35 秒）、`skip()`、Esc、`settle()` 清行內樣式、`takeFlag()`；訂單資料與單品資料的載入照舊。
- `scripts/member-check.mjs`：七項——第二步滑進來後停在原位；完成頁剛到是 playing 且有跳過；2.4 秒後自己結束（衣服沒有行內樣式、`opacity` 1、一行字可見、跳過消失、提袋沒有殘留的 `transform-origin`）；再放記號重載 1.1 秒時還在播 → 跳過 → 狀態和自己播完的逐欄位相同；重新整理不播；貨到付款那張用 `Emulation.setEmulatedMedia` 模擬減少動態 → 一到就是靜止、沒有跳過。

## 容易錯的地方

- **類別撞名**：`GarmentImage` 自己的根也叫 `.garment`，衣服的外框叫 `.drop`——第一版叫 `.garment`，驗收數出兩個元素、其中一個帶 `GarmentImage` 的 `--h` 行內變數。
- **`clearProps` 要清到 `transform-origin`**：提袋壓一下用了 `transformOrigin`，只清 `transform,opacity` 會留下 `transform-origin: 50% 100%`——驗收抓到的，改成 `all`。
- **`progress(1)` 會觸發 `onComplete`**：跳過和播完走同一個 `settle()`，別再各寫一份。
- **記號是每張訂單一個**：同一個完成頁的網址重開不會再播；要再看一次就把記號放回去（驗收這麼做）。
- **Esc 的監聽要在離開頁面時拿掉**。

## 實測了什麼

- `member-check` 從 61 項長到 **68 項**，桌機 1252×699 與手機 390×844 全過；`shop-check` 60／60 兩種尺寸；`a11y-check` 兩種尺寸 axe 0 違規、鍵盤 20 步（第二步滑進來後 500 毫秒內標題有焦點）；`expand-check` 桌機 218／手機 208；`check:contrast` 55 組。
- 第一次跑抓到兩個真問題（上面「容易錯」的前兩項），都是驗收在比「播完的靜止狀態」時量出來的；修完全綠。
- 截圖看過：`checkout-done`（剛到、衣服在半空、右上有跳過）、`done-resting`（衣服站在袋裡、一行字），桌機與手機。
- 這一段的時間比例（0.7 秒落下、0.12 錯開、1.2–1.6 秒全長）是設計假設，沒有使用者看過。
