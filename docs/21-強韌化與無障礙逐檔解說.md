# 21　第十七輪・子輪 2：全站強韌化與無障礙

2026-10-10。規格在 [19](19-訂單全程與強韌化-規格.md) §4。功能規劃 7 的「狀態畫面：每頁三態」「錯誤頁：伺服器錯誤」是 `必`；1.1 的鍵盤操作、9 的尊重減少動態是 `特`。從第十輪起每份解說都寫「讀屏、鍵盤沒驗證」——這一輪把能用儀器量的部分量了。自主探索的第五個子輪，設計沒有一項經過確認。

## 做了什麼（一句話）

沒接住的錯誤會落到「出了點問題」的畫面（重新載入、回入口），換版本後的舊分頁會自己重載一次；換頁時焦點移到新頁面的標題、讀屏聽到「已前往 X」；探索區每一頁載入失敗都有字和「再試一次」（用一個開發版的失敗開關驗）；axe-core 掃了 29 個頁面狀態到 0 違規，天空上的字用截圖量像素，購買路徑只用鍵盤走得完。

## 設計怎麼定的

- **錯誤邊界自己畫整個畫面**：錯誤可能就是頂欄丟的，所以不套框架；兩條路都是整頁重載（狀態從頭來最保險）；第一個錯誤最接近原因，後面的不覆蓋；開發版把錯誤印在畫面上，正式版只進主控台。
- **舊分頁重載一次，不無限重載**：Vite 文件說 chunk 載不到會送 `vite:preloadError`（讀過文件，規格 §1）。30 秒內沒重載過就重載，重載過還失敗就是部署真的壞了，交給錯誤畫面。
- **只在路徑改變時移焦點**：一句話列只改查詢字串，鍵盤使用者的焦點正在下拉格上，不能被拉走。焦點移到第一個 `h1`，頁面還在載入、h1 還沒畫出來就落在 `main`（`tabindex="-1"`，不畫外框）；不捲動——捲動歸 `scrollBehavior` 管。播報用一個 `aria-live="polite"` 的隱藏區塊，先清空再寫，同一句才會再唸一次。
- **失敗開關是正控的一半**：`localStorage.apiFail` 寫函式名，假 API 就丟 `NETWORK`；驗收先開再關——關掉要全好，開著要有字。正式版不認。
- **載入失敗和「找不到」分開**：路線頁與活動頁以前一律「找不到」，現在失敗會寫「沒有載入成功」並能再試。首頁第一屏、這一週、試穿間、我的偏好也補了字。活動插卡與「最近看過」是次要內容，失敗就不顯示，這是刻意的。
- **axe 只跑 WCAG 2.0／2.1 的 A 與 AA**：best-practice 噪音多，先不當門檻。它抓不到的部分（讀屏實際怎麼唸、焦點順序合不合理）仍要真人。
- **天空上的字另外量**：axe 看不到 WebGL 畫布——桌機它判「無法判定」，手機它把站名判成淺字壓在紙色上。後者是真的：窄螢幕的頂欄不在天空上，卻跟著天空換色。量法：把那個元素的字藏起來（`visibility: hidden`，版面不動）、截那一塊、算背景像素的平均亮度，再和文字顏色算 WCAG 對比度；四個時刻（開發版 `?hour=`）各量一次。
- **天空的字色改用對比度決定**：原本「太陽高度 > 0.08 就深字」，清晨與傍晚天空是中間調，深字只有 2.5–3.0:1。現在照著色器同一套顏色模型估天空在文字那一帶的亮度，深字與淺字各算對比度，誰高用誰（`estimateSkyColour`、`skyWantsDarkText`）。白天頂欄的深字再深一點（`#0f1118`）：站名在天頂的藍上量到 4.47，差 0.03。
- **鍵盤走法照真的鍵盤**：Tab、Shift+Tab、Space、Enter、方向鍵；同一組 radio 用方向鍵換（Tab 只進到群組）；從購買區塊回頂欄用 Shift+Tab（往前要繞過整個頁尾）。

## 容易錯的地方

- **`errorHandler` 會把任何沒接住的錯誤變成整頁錯誤畫面**：這是故意的（功能規劃 7 要的是不留白頁），但也表示一個小元件的錯誤會蓋掉整頁。開發版會印出來，正式版要看主控台。
- **`unhandledrejection` 也算**：頁面裡沒 `catch` 的 `await` 都會觸發；目前全站跑過三支驗收沒有誤觸。
- **`vite:preloadError` 在開發版不會自然發生**（沒有 chunk）；驗收是手動送事件。正式版才會遇到真的。
- **焦點移到 `main` 那一瞬間**：商品頁、穿搭頁的 h1 要等資料；這時焦點在 `main`，讀屏唸「已前往 商品頁」。之後 h1 出現不再搬焦點（搬了會打斷正在 Tab 的人）。
- **失敗開關只有開發版認**：`import.meta.env.DEV` 為假時直接回傳，正式版連 localStorage 都不讀。
- **天空字色的估算不含雜訊與太陽**：雲是用覆蓋率的平均算的，所以估的是平均亮度；量像素是最後的裁判。

## 實測了什麼

- **axe-core**（WCAG 2.0／2.1 A＋AA）：第一次掃桌機 29 個頁面狀態抓到 10 處、三種規則（`aria-prohibited-attr` 七頁、`link-name` 穿搭頁三個縮圖、`color-contrast` 放大看的關閉），手機多一處（站名，真的錯：窄螢幕頂欄夜裡淺字壓紙色）。修完兩種尺寸都是 **0 違規**；每頁另有 1–3 項「無法判定」（天空畫布上的對比度那類），不當結論。
- **天空上的字**（截圖量像素，WCAG 公式）：桌機與手機各 12 組（06／12／18／22 點 × 站名、頂欄第一個字、第一屏 h1）全合格。改之前：桌機 06:00 的 h1 2.99（門檻 3）、手機 2.45、正午站名 4.47（門檻 4.5）；改之後：06:00 h1 桌機 6.50、手機 7.57（改用淺字），正午站名 5.01，夜裡站名 14.04。手機頂欄四個時刻都是 15.85（墨色在紙色上）。今天的天氣是雨（雲量 0.92），晴天沒量。
- **只用鍵盤**：單品列表 → 商品頁 → 選尺寸 → 加入購物車 → 回頂欄 → 購物車 → 結帳兩步 → 訂單完成，20 步全到；Tab 次數：到第一件單品 8、到有貨的尺寸 7、到加入購物車 5、Shift+Tab 回購物車圖示 13、到去結帳 6、地址 1、下一步 2、付款方式群組 1、送出 2。第一下 Tab 是「跳到主要內容」，Enter 後焦點真的在 `main`。
- **`expand-check` 第 9 段 17 項**：桌機 218／218、手機 208／208。失敗開關開著時首頁第一屏、店、這一週、穿搭頁、路線頁、活動頁、單品列表、試穿間都有字；關掉後試穿間按「再試一次」就載進來、首頁全好；換頁後 `document.activeElement` 是 h1、播報「已前往 穿搭」；只改查詢字串焦點留在一句話列；沒接住的 Promise → 出了點問題、重新載入回來；`vite:preloadError` 第一次重載（`performance` 的 navigation type 是 `reload`）、30 秒內第二次改給錯誤畫面。
- `member-check` 61、`shop-check` 60（桌機與手機）沒退；`check:contrast` 55 組；改動的文字檔無 BOM、無 CR。
- **一個沒解開的觀察**：手機尺寸的 `expand-check` 今天跑了五次，第十五輪就有的「下拉格鍵盤」那六項有兩次紅（第三段：按鈕上按 ArrowDown 之後 250 毫秒內 `[role=listbox]` 沒出現、`aria-expanded` 還是 false，後面的勾選跟著全紅；其中一次是和另外兩支腳本同時跑、一次是單獨跑），其餘三次全綠，包括一次在同一位置加了探針的版本（焦點在按鈕上、keydown 有到、清單有開）。桌機從來沒紅過；兩支直接探針（含先走過前面三個篩選網址）也都開得了。這一段在第十五、十六輪的所有手機跑都是綠的，所以不排除是這一輪的改動（換頁焦點、天空字色）和它有時序上的關係，但沒抓到機制。先記在這裡，下一輪再看。
- 儀器教訓：無頭 Chrome 的頁面預設沒有焦點，Tab 按了不動（18 項全紅、`activeElement` 一直是 body）——要 `Emulation.setFocusEmulationEnabled`；沒有文字的鍵用 `rawKeyDown`；Chrome 把 `color-mix` 算出來的顏色寫成 `color(srgb 0.1 0.1 0.15)`，當成 0–255 會算成全黑；JS 的 `-(x) ** 2` 是語法錯誤。
- 截圖看過：`fatal`（出了點問題）、`keyboard-done`（鍵盤走到的訂單完成頁）。

## 沒有驗證

- 真的讀屏（NVDA、VoiceOver）怎麼唸時間線、一句話列、播報；axe 的「無法判定」那幾項。
- 正式版（Pages）上真的 chunk 載入失敗——開發版沒有 chunk，驗收是送假事件。
- `errorHandler` 在正式版會不會被不該算錯誤的東西觸發（三支驗收沒有誤觸，真人用過才知道）。
- 晴天與其他時刻的天空（量的是今天的雨天、四個整點）；真的手機。
