# 01 全站骨架解說

這份文件解釋第一版骨架裡每個檔案在做什麼、為什麼這樣寫。讀的順序就是程式啟動的順序。
所有「為什麼」都是我（Claude）的選擇，不是唯一做法；11/16 上過 Vue 課後，寫法和老師教的不一樣的地方再對齊。

## 怎麼跑

```bash
npm install
```

```bash
npm run dev
```

開 <http://localhost:5183>。另外兩個指令：

```bash
npm run build
```

```bash
npm run check:contrast
```

`build` 產生正式版到 `dist/`；`check:contrast` 計算全站文字與背景的對比度，有不合格就失敗。

## 這一版做了什麼、沒做什麼

做了：頂欄、一句話列、穿搭卡舞台、交易區的置中單欄、頁尾、主題色跟著走、全部頁面的路由、假資料 API 層。

沒做：入口場景（主題島）、所有交易區頁面的實際內容、商品頁、搜尋、登入。這些頁面的網址都已經存在，打開會看到一個說明「這頁要放什麼」的佔位畫面。

## 1. 啟動：`index.html` → `src/main.js` → `src/App.vue`

瀏覽器先拿到 `index.html`。裡面只有一個空的 `<div id="app">` 和一行載入 `src/main.js`。這就是「單頁應用」：伺服器永遠只給這一頁，之後換頁都是 JavaScript 在同一頁裡換內容。

`src/main.js` 做三件事：建立 Vue 應用、掛上路由（`.use(router)`）、把應用放進 `#app`。另外載入兩個全站樣式檔。

`src/App.vue` 是最外層的框架。它的模板從上到下是：

1. 「跳到主要內容」連結：平常看不到，鍵盤使用者按第一下 Tab 才出現，可以跳過頂欄。
2. `<SiteHeader />` 頂欄。
3. `<SentenceBar />` 一句話列，只有路由標了 `sentence: true` 的頁面才出現。
4. `<main>` 裡的 `<RouterView />`：目前網址對應的那一頁會被放在這裡。
5. `<SiteFooter />` 頁尾。

**探索區和交易區只差一個 class。** `App.vue` 讀目前路由的 `meta.zone`，是 `explore` 就給 `<main>` 加 `stage`（最寬 80rem），否則加 `column`（最寬 38rem、置中）。我沒有做兩個版面元件，因為兩區的差別目前只有寬度和一句話列，一個 class 就夠；之後差別變多再拆。

`.vue` 檔的三段：`<script setup>` 是這個元件的程式，`<template>` 是它的 HTML，`<style scoped>` 是只對這個元件生效的 CSS（`scoped` 讓 Vue 自動替選擇器加上識別碼，不會影響到別的元件）。

## 2. 路由：`src/router/index.js`

一個陣列列出全站所有網址。每一筆有：

- `path`：網址。`:code`、`:id` 這種寫法是參數，例如 `/themes/street` 的 `code` 就是 `street`。
- `name`：路由的名字。程式裡換頁用名字（`{ name: 'theme', params: { code: 'street' } }`），之後改網址時不用到處改字串。
- `component: () => import(...)`：寫成函式，這一頁的程式要到第一次進去才下載，首頁不會被還沒做的頁面拖慢。
- `meta`：我自己加的附註。`zone` 決定版面；`sentence` 決定有沒有一句話列；`level` 和 `note` 只給佔位畫面顯示。

頁面的分區照 vault 筆記〈前台介面方向〉第 2.1 節的表。還沒做的頁面全部指向同一個 `PlaceholderView.vue`。

最後一筆 `/:pathMatch(.*)*` 會接住所有沒列出的網址，顯示「找不到這個頁面」。它一定要放最後。

`scrollBehavior` 決定換頁時捲到哪裡：按上一頁回到離開時的位置；同一頁只是換篩選條件就留在原地；其他情況回到頂端。

`router.afterEach` 在每次換頁後更新瀏覽器分頁的標題。

## 3. 設計變數：`src/styles/tokens.css`、`src/styles/base.css`

`tokens.css` 用 CSS 變數把全站的顏色、字級、間距集中在一處。幾個決定：

- **顏色依用途命名**（`--ink` 主要文字、`--accent` 強調色），不依外觀命名（不叫 `--dark-grey`）。換配色只改這個檔案。
- **字級只有五級**（`--fs-0` 到 `--fs-4`），全站用字級加粗細表達層級，不隨手寫新的大小。
- **單位用 rem**。使用者在瀏覽器裡把預設字級調大，整個版面會跟著放大，不會破版。
- **間距是基礎行高 1.6rem 的 1/4、1/2、1、2 倍**，上下的節奏會一致。
- 這一版只有亮色，沒有做暗色主題。

`base.css` 是全站共用的基本樣式：字型、標題大小、鍵盤焦點外框、`.btn` 主要按鈕、`.visually-hidden`（畫面上看不到但讀屏讀得到）。最後一段在系統設定「減少動態」時關掉全站的轉場。

字型用系統內建的（Noto Sans TC、蘋方、微軟正黑體依序找），沒有從網路載入字型，所以不同電腦上的字會不一樣。要統一字型是之後的決定。

## 4. 主題色：`src/theme/themes.js`、`src/composables/useThemeAccent.js`

`themes.js` 是一張表：主題代碼 → 強調色。主題的名稱和說明來自 API，顏色定義在前端，兩邊用代碼對應。之後入口場景的圖樣也會放在這張表裡。**五個主題和它們的顏色都是暫定的**，正式清單要全組決定。

`useThemeAccent.js` 實作「主題色跟著走」。它監看目前的路由，只要進到 `/themes/某代碼`，就把 `<html>` 上的 `--accent` 變數改成那個主題的顏色。全站所有用到 `var(--accent)` 的地方（按鈕、底線、焦點外框、購物車件數）會同時換色，不用一個一個改。它把代碼存進 `sessionStorage`，重新整理後顏色還在，關掉分頁就回到預設。網址上的代碼不存在時不動作。

`composables/` 資料夾放「可以被多個元件共用的一段邏輯」，Vue 的慣例是函式名以 `use` 開頭。

**對比度**：強調色同時當按鈕的底色（上面放白字）和頁面上的底線，兩種用法都要夠清楚。`npm run check:contrast` 會算出每一組的數值。目前 24 組都合格，最低的是表單邊框對頁面底色 4.18（門檻 3）和佔位圖上的次要文字 5.59（門檻 4.5）。改任何顏色之後要重跑。

## 5. 假資料 API：`src/api/`

`src/api/index.js` 匯出三個函式：`getThemes()`、`getWeather()`、`getOutfits(filters)`。畫面只呼叫這三個函式，不直接讀 JSON。

這一層的用途是把「資料從哪來」和「畫面怎麼畫」分開。現在函式裡面讀的是 `mock/` 底下的 JSON；後端 API 做好以後，把函式內容換成 `fetch`，畫面的程式一行都不用改。每個函式都故意等一小段時間才回傳，開發時才看得到「載入中」的畫面。

**資料欄位是我先假設的**，要和負責後端的組員對過才算數。特別是「穿搭組合」這個東西（一組穿搭包含哪幾件單品），後端目前沒有這張表。

假資料裡的品牌名（霧岸、半日、夜班車、拾穗製衣、舊課本、野徑）是我編的，沒有查過是否和真實品牌撞名，定案前要查。

## 6. 篩選條件：`src/composables/useFilters.js`、`src/filters/options.js`

**篩選條件只存在網址裡**，程式裡沒有另一份。風格是路徑的一部分（`/themes/street`），場合、類別、尺寸是查詢字串（`?occasion=work&size=M`）。這樣重新整理、按上一頁、把連結貼給別人，看到的都是同一組條件，功能清單把這一點列為必做。

`useFilters()` 回傳兩樣東西：

- `filters`：從目前網址算出來的條件。它是 `computed`，網址一變它就自動更新。
- `setFilter(key, value)`：改某一格條件，做法是換網址。換風格用 `router.push`（等於換一頁，按上一頁會回到前一個主題）；換其他三格用 `router.replace`（不在瀏覽紀錄裡多一筆，不然調三次條件就要按三次上一頁）。

`options.js` 是場合、類別、尺寸三格的選項表。每個選項有三個字串：`value` 給 API、`label` 放進句子裡、`short` 用在收合後的摘要。

## 7. 一句話列：`src/components/SentenceBar.vue`

畫面上的「今天 18°C，〔哪裡都去〕，想穿〔什麼風格都好〕，找〔整套穿搭〕，尺寸〔不限〕。」

- **每一格是真的 `<select>`**，只是把外框拿掉、加一條底線。好處是鍵盤能操作、讀屏會唸出欄位名稱、手機會跳出原生的選單，這些都不用自己做。每個 `<select>` 包在 `<label>` 裡，裡面有一段視覺隱藏的文字（場合、風格、類別、尺寸）當欄位名稱。
- `:value="filters.occasion"` 讓選單顯示網址上的值；`@change="setFilter(...)"` 在使用者改選時去改網址。資料只往一個方向流：網址 → 選單顯示；使用者操作 → 改網址 → 選單跟著變。
- **捲動收合**：往下捲超過 160 像素就收成一行摘要（例如「18°C · 街頭」），點「改條件」再展開。收合和展開用兩個不同的門檻（160 和 60），因為收合會讓頁面變矮，同一個門檻會在邊界上來回閃。
- 每一小段（含後面的標點）包在不換行的 `.clause` 裡，視窗變窄時整段一起換行，逗號不會掉到下一列的開頭。
- 天氣或主題清單拿不到時，句子少一段或風格那一格只剩「不限」，不會整列壞掉。
- `onMounted` 掛上捲動監聽，`onBeforeUnmount` 拿掉。凡是自己掛上去的監聽，都要在元件離開時自己拿掉。

句子的文字是我寫的草稿，要你自己看順不順。

## 8. 穿搭卡舞台：`src/components/OutfitStage.vue`、`OutfitCard.vue`

`OutfitStage.vue` 負責要資料和排版：

- `watch(filters, load, { immediate: true })`：網址上的條件一變就重新要資料，元件一出現也先要一次。
- **三種狀態都有畫面**：載入中、出錯（附「再試一次」）、沒有符合的結果（附「看全部穿搭」）。功能清單把這一點列為每一頁的必做項目。
- `latest` 這個計數器處理一個不明顯的問題：連續改兩次條件時，第一次的請求可能比第二次晚回來，畫面會被舊結果蓋掉。每次送出請求就把計數加一，回來時發現自己不是最新的那一次就丟掉。
- **不對稱格線**：12 欄，卡片寬度每六張循環一次（4-5-3／3-5-4 欄）。中等寬度改成兩張一列，窄螢幕一張一列。在 1280 像素寬的視窗量到的卡片寬度是 388、491、284、284、491、388。

`OutfitCard.vue` 是一張卡：佔位圖、標題、主題與件數與總價、單品清單、「整套加入購物車」。

- 圖片還沒有，先用一塊同比例（4:5）的淡色塊佔位。
- 單品名稱是連到商品頁的連結。
- 金額用 `tabular-nums`（等寬數字）靠右，上下列的位數才對得齊。
- 按下「整套加入購物車」後，按鈕旁邊出現「已加入 N 件」兩秒。這段文字放在 `role="status"` 的元素裡，讀屏會自動唸出來。
- 尺寸的處理見下面「還沒決定的事」第 3 點。

## 9. 購物車：`src/stores/cart.js`

目前只夠讓頂欄顯示件數。`lines` 宣告在模組的最外層，所以全站共用同一份；任何元件呼叫 `useCart()` 拿到的都是它，卡片加了東西，頂欄的數字就跟著變。內容存在瀏覽器的 `localStorage`，重新整理後還在。

之後購物車頁要做的時候，這個檔案會長大（改數量、刪除、登入後和會員購物車合併）。到時候可能換成 Pinia（Vue 官方的狀態管理），現在這個大小還用不到。

## 10. 頁面：`src/views/`

- `HomeView.vue`：目前是「一般模式」的首頁——一句定位、五張主題卡、全部穿搭。入口場景做好後接在主題卡的位置。
- `ThemeView.vue`：主題頁——主題名稱與說明、該主題的穿搭。主題代碼不存在時顯示「找不到這個主題」。這裡用 `computed` 找主題而不是在 `onMounted` 裡找一次，因為從一個主題換到另一個主題時，Vue Router 會沿用同一個元件、只換網址參數，`onMounted` 不會再跑。
- `OutfitsView.vue`：全部穿搭。
- `PlaceholderView.vue`：還沒做的頁面共用。
- `NotFoundView.vue`：網址不存在。

## 驗證了什麼、沒驗證什麼

在內建瀏覽器實際操作過（1280×800 與 375×812 兩種寬度）：

- 首頁出現 5 張主題卡、8 張穿搭卡、4 個下拉選單。
- 場合選「去上班」→ 網址變成 `?occasion=work`，剩 2 張卡；再選類別「配件」→ 0 張，出現空狀態。
- 風格選「街頭」→ 網址變成 `/themes/street`，標題變「街頭」，強調色變成 `#a8281f`，按鈕底色跟著變。
- 按上一頁回到首頁，條件還在，強調色維持。
- 「整套加入購物車」→ 頂欄顯示 4 件。
- 往下捲 → 一句話列收成「18°C · 街頭」；點「改條件」→ 展開。
- `/cart` 是置中單欄（608 像素寬）、沒有一句話列；`/no/such/page` 顯示找不到頁面；`/themes/nope` 顯示找不到主題，而且不改動強調色。
- 兩種寬度都沒有水平捲軸。
- `npm run build` 成功；`npm run check:contrast` 24 組合格。

沒有驗證：

- 只在這台電腦的內建瀏覽器（Chromium）看過；Firefox、Safari、實體手機都沒試。`field-sizing: content`（讓下拉選單的寬度跟著選到的字）在不支援的瀏覽器會退回原本的寬度，沒有實際看過退回後的樣子。
- 沒有用讀屏軟體實際聽過；鍵盤操作只確認了欄位有名稱，沒有從頭 Tab 走完一遍。
- 「減少動態」的設定沒有實際切換測試。
- 沒有自動化測試。
- 開發過程中主控台出現過兩則錯誤，發生在我分兩次存檔的中間狀態；重新載入後頁面運作正常，但瀏覽器工具的紀錄不會隨重新載入清空，所以我沒辦法用它證明「重新載入後零錯誤」。

## 還沒決定的事（需要你或全組決定）

1. **「場合」這一格沒有對應的後端資料。** 功能清單的篩選條件裡沒有場合。要嘛後端在穿搭組合上加場合標籤，要嘛拿掉這一格。
2. **頂欄的「穿搭牆」「天氣穿搭」連結。** 功能清單的導覽列有這兩項，佈局草圖沒有。分類選單拿掉後，內頁沒有別的路到這兩頁，所以我先留著；你要拿掉就說。
3. **整套加入購物車時尺寸還沒選。** 現在的做法：一句話列選了尺寸、而且該單品有這個尺寸就帶入；只有單一尺寸的直接帶入；其餘記為「未選」，留到購物車補選。
4. **站名**「今天穿什麼」是我暫放的，只在 `src/config.js` 一處。
5. **首頁那句定位**「幫你決定今天穿什麼，而且買得合身。」來自功能規劃的建議，不是定案。
6. **主題頁的穿搭太少時右邊會空一大片**（例如復古只有一套）。這是假資料太少造成的，真資料進來後要再看一次版面。
