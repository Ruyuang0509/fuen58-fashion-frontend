## 1. 參考與查證（2026-10-10；證據狀態照 vault 規則標）

- **WAI-ARIA APG 的 combobox 樣式**——`content-validated`：讀了 w3.org/WAI/ARIA/apg/patterns/combobox/。輸入框 `role="combobox"`、`aria-expanded`（清單開著才 true）、`aria-controls` 指向清單（開著時）、`aria-autocomplete="list"`；清單 `role="listbox"`、選項 `role="option"`；「DOM focus remains on the combobox」，用 `aria-activedescendant` 指目前的選項；鍵盤：Down／Up 移動並選取、Enter 接受、Escape「Closes the popup and returns focus to the combobox」、Tab 時清單與選項不在 Tab 順序裡。→ 搜尋建議照這個做；和第十五輪的下拉格（`ClausePicker`，焦點在 listbox 上）是兩種合法做法，各有各的規範。
- **折扣碼**——沒有新查證；規則（滿額折、打折上限、免運、過期）是常見做法的〔本專案〕版本，數字是示範值。
- **一般模式**——沒有外部來源；功能規劃 1.1 的原文：「畫面上固定有切換鍵，可改用普通首頁；記住使用者的選擇」「瀏覽器不支援或 3D 初始化失敗時，自動走一般模式」。後者第十一輪已有（`createSky` 拿不到 WebGL 就畫 CSS 漸層）。

## 2. 原則

1. **切換要真的切**（claude-art L2 #15 的精神）：選了一般模式，WebGL 就真的不建、動畫就真的不跑；驗收量 `data-sky`、`<html>` 的 class、計算出的 `transition-duration`。
2. **記在本機、整頁重載**：模式一改就 `location.reload()`——很多元件在掛載時就記住了「要不要動」，重載最誠實；畫面上寫「切換會重新載入這一頁」。
3. **建議不替人搜**：搜尋建議只列最多 5 件單品、3 個品牌、3 條路線加一行「搜尋「X」的單品」；按 Enter 沒選到任何建議時照舊去結果頁。
4. **折扣只在後端算數**：前台先驗代碼給回饋，正式版金額以 `POST /api/orders` 回的為準（契約 §8 本來就這樣寫）。

## 3. 子輪 1：一般模式與對照表

- `src/stores/motion.js`：`mode`（`auto`｜`reduce`｜`plain`，localStorage `motion`）；`isReduced()`＝不是 auto，或系統設定減少動態；`isPlain()`；在 `<html>` 掛 `reduce-motion` class 與 `data-motion`；`set()` 存了就重載。`main.js` 一開站載入。
- `src/motion/gsap.js` 的 `reducedMotion()` 改讀 store；`useFlyToCart`、`SiteFooter` 兩處直接問 `matchMedia` 的改成同一個來源。`base.css` 加 `html.reduce-motion` 的全域規則（和 `prefers-reduced-motion` 那段一樣：transition、animation 歸零）。元件裡各自的 `@media (prefers-reduced-motion)` 區塊只管系統設定——它們做的事和全域規則重疊（關過渡），差異列在解說裡。
- `src/sky/sky.js`：`createSky(canvas, { reduced, plain })`，`plain` 就走沒有 WebGL 的那條（CSS 漸層）。`SkyPage` 在畫布上標 `data-sky="webgl|css"`、`data-motion="live|static"`（驗收用）。
- 頁尾「關於」那欄下面一列：「畫面」`<select id="motion-mode">` 三個選項；自動那項會寫「（系統目前是減少動態）」。
- `docs/23`：對照表。
- 驗收（`expand-check` 第 10 段）：預設 webgl／live／沒有 class；選一般模式 → 重載 → `data-sky=css`、class 在、選單記得、localStorage 有、探針元素的 `transition-duration` 是 0s；選減少動態 → webgl／static／class 在；選回自動 → 正控全回來（探針 1s）。

## 4. 子輪 2：搜尋建議

- 頂欄搜尋框打字（至少一個字、去頭尾空白）150 毫秒後查：單品（`searchProducts`，最多 5）、品牌（名字含關鍵字，最多 3）、路線（最多 3）、最後一行「搜尋「X」的單品」。清單在輸入框下面（`role="listbox"`），輸入框是 `role="combobox"`，焦點不離開輸入框，用 `aria-activedescendant` 指目前這一項。
- 鍵盤：Down／Up 移動（到底會繞）、Enter 走目前那一項（沒有就照舊去結果頁）、Esc 第一下關清單、第二下關搜尋框（原本的行為）、Tab 關清單。滑鼠：點一項就走。
- 手機（≤ 36rem）：搜尋列蓋在頂欄上時，清單接在頂欄下面整寬。
- 結果列只有名字與一個小標（單品的品牌、品牌寫「品牌」、路線寫「路線」），不放縮圖——頂欄裡要輕。
- 驗收（`expand-check` 第 11 段）：打「大衣」→ 清單有單品、每一項是 option、`aria-expanded` 真、焦點還在輸入框；Down 兩下 → `aria-activedescendant` 指第二項；Enter → 到那件商品頁；打「霧」→ 有品牌「霧岸」→ 點它 → `/brands/wuan`；打「zzz」→ 只剩「搜尋「zzz」的單品」；Esc → 清單關、`aria-expanded` 假、焦點在輸入框。axe 掃搜尋開著的狀態。

## 5. 子輪 3：折扣碼

- `src/api/mock/coupons.json`：`WELCOME100`（滿 1,000 折 100）、`AUTUMN15`（85 折，最多折 500）、`SHIPFREE`（免運）、`SPRING2026`（已過期）。
- 假 API：`checkCoupon(code, subtotal)` → `{ code, label, discount, freeShipping }` 或 `ApiError('COUPON_INVALID', 訊息)`（沒有這個折扣碼／已過期／未達門檻 N 元）；`createOrder` 多收 `couponCode`，重算 `discount`、`shipping`（免運門檻看折扣後的小計；免運券直接 0）、`total`，訂單多 `coupon`、`discount` 欄。
- 結帳第二步：「折扣碼」輸入＋「套用」（Enter 也行）；套用成功寫「已折 N 元」或「免運」、可「取消折扣」；金額區多「折扣」一列。訂單明細、完成頁、訂單紀錄的合計跟著。
- 契約：§8 的 `POST /api/orders` 多 `couponCode`，訂單多 `coupon`／`discount`；新 §16 `GET /api/coupons/:code?subtotal=`；§15 加 `COUPON_INVALID`。
- 驗收（`member-check`）：結帳套用不存在的碼 → 行內錯誤；`WELCOME100` 在 280 元 → 未達門檻；`SHIPFREE` → 運費 0、合計 280；下單後訂單明細有「折扣」或「免運（SHIPFREE）」；取消折扣 → 金額回去。
